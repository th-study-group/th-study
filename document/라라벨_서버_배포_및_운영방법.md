# Laravel 운영 서버 배포 및 운영 매뉴얼

이 문서는 AWS Lightsail의 Ubuntu 22.04 LTS 서버에 Laravel 12 프로젝트를 배포하고 운영할 때 필요한 설정을 순서대로 정리한 문서입니다.

기준 환경은 다음과 같습니다.

```text
AWS Lightsail
Ubuntu 22.04 LTS
Nginx
PHP 8.2
MySQL 8
Node.js 20
Composer 2
Laravel 12
프로젝트 경로: /var/www/th-study
도메인: https://www.th-study.com
```

실제 비밀번호, API 키, JWT 키, VAPID 키는 문서와 Git 저장소에 기록하지 않습니다.

---

## 1. AWS Lightsail 인스턴스 생성

AWS Lightsail에서 Ubuntu 인스턴스를 생성합니다.

```text
플랫폼: Linux/Unix
운영체제: Ubuntu 22.04 LTS
메모리: 2GB 이상 권장
인스턴스 이름: th-study
```

인스턴스를 생성한 뒤 고정 IP를 연결합니다.

```text
Lightsail
→ Networking
→ Create static IP
→ 생성한 인스턴스 연결
```

Lightsail 방화벽에 다음 포트를 등록합니다.

```text
22  SSH
80  HTTP
443 HTTPS
```

MySQL 포트인 `3306`은 외부에 공개하지 않습니다.

---

## 2. 도메인 DNS 연결

도메인 관리 사이트에서 Lightsail 고정 IP를 연결합니다.

```text
A      @      LIGHTSAIL_STATIC_IP
A      www    LIGHTSAIL_STATIC_IP
```

또는 `www`를 CNAME으로 연결합니다.

```text
A       @      LIGHTSAIL_STATIC_IP
CNAME   www    th-study.com
```

DNS 적용 여부를 확인합니다.

```bash
nslookup th-study.com
nslookup www.th-study.com
```

출력되는 IP가 Lightsail 고정 IP와 같아야 합니다.

## 3. SSH 접속

Windows PowerShell에서 다음 명령으로 접속합니다.

```powershell
ssh -i "C:\키파일경로\LightsailDefaultKey.pem" ubuntu@LIGHTSAIL_STATIC_IP
```

macOS 또는 Linux에서는 키 파일 권한을 설정한 뒤 접속합니다.

```bash
chmod 400 ./LightsailDefaultKey.pem
ssh -i ./LightsailDefaultKey.pem ubuntu@LIGHTSAIL_STATIC_IP
```

처음 접속할 때 다음 질문이 나오면 `yes`를 입력합니다.

```text
Are you sure you want to continue connecting?
```

## 5. Swap 설정

2GB 서버에서는 Composer 설치나 npm 빌드 중 메모리가 부족할 수 있으므로 Swap을 설정합니다.

현재 Swap 상태를 확인합니다.

```bash
free -h
swapon --show
```

2GB Swap 파일을 생성합니다.

```bash
sudo fallocate -l 2G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile
```

재부팅 후에도 유지되도록 설정합니다.

```bash
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
```

적용 여부를 확인합니다.

```bash
free -h
swapon --show
```

## 9. PHP 운영 설정

```bash

```

다음 값을 수정합니다.

```ini

upload_max_filesize = 50M
post_max_size = 50M
max_execution_time = 60
max_input_time = 60
date.timezone = Asia/Seoul
expose_php = Off
display_errors = Off
log_errors = On
```

설정 후 PHP-FPM을 재시작합니다.

```bash
sudo systemctl restart php8.2-fpm
```

## 20. Nginx 서버 블록 설정

서버 블록 파일을 생성합니다.

```bash
sudo nano /etc/nginx/sites-available/th-study
```

다음 내용을 입력합니다.

```nginx
server {
    listen 80;
    listen [::]:80;

    server_name th-study.com www.th-study.com;

    root /var/www/th-study/public;
    index index.php index.html;

    charset utf-8;

    access_log /var/log/nginx/th-study.access.log;
    error_log /var/log/nginx/th-study.error.log;

    client_max_body_size 50M;

    location / {
        limit_req zone=thstudy_limit burst=20 nodelay;
        try_files $uri $uri/ /index.php?$query_string;
    }

    location ~ \.php$ {
        include snippets/fastcgi-php.conf;
        fastcgi_pass unix:/run/php/php8.2-fpm.sock;
    }

    location ~ /\.(?!well-known).* {
        deny all;
    }

    location ~* \.(env|log|sql|bak|old|swp)$ {
        deny all;
    }
}
```

서버 블록을 활성화합니다.

```bash
sudo ln -s \
/etc/nginx/sites-available/th-study \
/etc/nginx/sites-enabled/th-study
```

기본 사이트를 비활성화합니다.

```bash
sudo rm -f /etc/nginx/sites-enabled/default
```

설정을 확인하고 반영합니다.

```bash
sudo nginx -t
sudo systemctl reload nginx
```

## 22. Queue Worker 설정

systemd 서비스 파일을 생성합니다.

```bash
sudo nano /etc/systemd/system/th-study-queue.service
```

다음 내용을 입력합니다.

```ini
[Unit]
Description=Laravel Queue Worker
After=network.target mysql.service php8.2-fpm.service

[Service]
User=www-data
Group=www-data
WorkingDirectory=/var/www/th-study
ExecStart=/usr/bin/php /var/www/th-study/artisan queue:work --sleep=3 --tries=3 --timeout=90
Restart=always
RestartSec=3

[Install]
WantedBy=multi-user.target
```

서비스를 등록하고 실행합니다.

```bash
sudo systemctl daemon-reload
sudo systemctl enable th-study-queue
sudo systemctl start th-study-queue
sudo systemctl status th-study-queue
```

실시간 로그를 확인합니다.

```bash
sudo journalctl -u th-study-queue -f
```

## 24. Nginx 로그 보관 설정

logrotate 설정 파일을 생성합니다.

```bash
sudo nano /etc/logrotate.d/nginx-th-study
```

다음 내용을 입력합니다.

```text
/var/log/nginx/th-study.access.log
/var/log/nginx/th-study.error.log {
    daily
    rotate 30
    missingok
    notifempty
    compress
    delaycompress
    create 0640 www-data adm
    sharedscripts

    postrotate
        systemctl reload nginx >/dev/null 2>&1 || true
    endscript
}
```

설정을 확인합니다.

```bash
sudo logrotate -d /etc/logrotate.d/nginx-th-study
```
