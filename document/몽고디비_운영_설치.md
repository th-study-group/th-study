# AWS Lightsail Ubuntu 22.04 운영 서버에 MongoDB 8.3.3 설치 및 설정하기

이 문서는 AWS Lightsail 2GB Ubuntu 22.04 서버에 MongoDB Community Server 8.3.3을 설치하고, 관리자 계정 생성, 인증 활성화, 서비스용 데이터베이스 생성, 서비스 계정 생성, 테스트 데이터 저장, MongoDB Compass 접속까지 진행하는 과정을 정리한 문서입니다.

## 1. 서버 환경 확인

먼저 Ubuntu 버전을 확인합니다.

```bash
lsb_release -a
```

Ubuntu 22.04 계열이면 아래와 비슷하게 표시됩니다.

```text
Distributor ID: Ubuntu
Description:    Ubuntu 22.04.x LTS
Release:        22.04
Codename:       jammy
```

이 문서는 Ubuntu 22.04 Jammy 기준으로 진행합니다.

## 2. 필수 패키지 설치

MongoDB 저장소 등록에 필요한 패키지를 먼저 설치합니다.

```bash
sudo apt update

sudo apt install -y curl gnupg
```

`sudo apt update`는 현재 서버가 알고 있는 패키지 목록을 갱신하는 명령입니다. 새로운 저장소를 등록하기 전후에는 패키지 목록 갱신이 필요하기 때문에 설치 과정에서 자주 사용합니다.

## 3. MongoDB GPG Key 등록

MongoDB 공식 저장소를 사용하기 위해 GPG Key를 등록합니다.

```bash
curl -fsSL https://pgp.mongodb.com/server-8.0.asc | \
sudo gpg --dearmor -o /usr/share/keyrings/mongodb-server.gpg
```

이미 같은 파일이 존재한다는 메시지가 나오면 덮어쓰기 여부를 묻습니다. 기존에 잘못 등록했거나 다시 설정하는 상황이라면 `y`를 입력하면 됩니다.

키 파일이 생성되었는지 확인하려면 아래 명령을 사용합니다.

```bash
ls -l /usr/share/keyrings/mongodb-server.gpg
```

## 4. MongoDB 8.3 저장소 등록

Ubuntu 22.04 Jammy 기준 MongoDB 8.3 저장소를 등록합니다.

```bash
echo "deb [ signed-by=/usr/share/keyrings/mongodb-server.gpg ] https://repo.mongodb.org/apt/ubuntu jammy/mongodb-org/8.3 multiverse" | \
sudo tee /etc/apt/sources.list.d/mongodb-org.list
```

등록된 저장소를 확인합니다.

```bash
cat /etc/apt/sources.list.d/mongodb-org.list
```

아래와 비슷하게 나오면 정상입니다.

```text
deb [ signed-by=/usr/share/keyrings/mongodb-server.gpg ] https://repo.mongodb.org/apt/ubuntu jammy/mongodb-org/8.3 multiverse
```

## 5. 패키지 목록 갱신

MongoDB 저장소를 새로 등록했으므로 패키지 목록을 다시 갱신합니다.

```bash
sudo apt update
```

## 6. 설치 가능한 MongoDB 버전 확인

현재 저장소에서 설치 가능한 MongoDB 버전을 확인합니다.

```bash
apt-cache madison mongodb-org
```

예시는 아래와 같습니다.

```text
mongodb-org | 8.3.4
mongodb-org | 8.3.3
```

이 문서에서는 로컬 개발 환경과 운영 서버 버전을 맞추기 위해 MongoDB 8.3.3 기준으로 진행합니다.

## 7. MongoDB 설치

MongoDB를 설치합니다.

```bash
sudo apt install -y mongodb-org
```

설치 후 버전을 확인합니다.

```bash
mongod --version
```

목표 버전은 아래와 같습니다.

```text
db version v8.3.3
```

## 8. MongoDB 버전 고정

운영 서버에서 의도치 않게 버전이 올라가는 것을 막기 위해 MongoDB 패키지 버전을 고정합니다.

```bash
sudo apt-mark hold \
mongodb-org \
mongodb-org-database \
mongodb-org-server \
mongodb-org-mongos \
mongodb-org-tools
```

고정 여부를 확인합니다.

```bash
apt-mark showhold
```

아래 패키지들이 표시되면 정상입니다.

```text
mongodb-org
mongodb-org-database
mongodb-org-mongos
mongodb-org-server
mongodb-org-tools
```

## 9. MongoDB 서비스 등록 및 시작

MongoDB가 서버 재부팅 후 자동으로 실행되도록 등록합니다.

```bash
sudo systemctl enable mongod
```

MongoDB를 시작합니다.

```bash
sudo systemctl start mongod
```

상태를 확인합니다.

```bash
sudo systemctl status mongod
```

정상 실행 중이면 아래와 같이 표시됩니다.

```text
Active: active (running)
```

MongoDB 기본 포트인 27017이 열려 있는지 확인합니다.

```bash
sudo ss -tulpn | grep 27017
```

기본 설정에서는 아래처럼 `127.0.0.1:27017`로 표시됩니다.

```text
127.0.0.1:27017
```

이 상태는 서버 내부에서만 MongoDB에 접속할 수 있는 상태입니다.

## 10. Mongo Shell 접속

MongoDB Shell에 접속합니다.

```bash
mongosh
```

접속 후 MongoDB 버전을 다시 확인할 수 있습니다.

```javascript
db.version()
```

## 11. 관리자 root 계정 생성

MongoDB 관리자 계정은 반드시 `admin` 데이터베이스에서 생성해야 합니다.

먼저 `admin` 데이터베이스로 이동합니다.

```javascript
use admin
```

현재 데이터베이스가 `admin`인지 확인합니다.

```javascript
db
```

결과가 아래처럼 나와야 합니다.

```text
admin
```

그 다음 root 계정을 생성합니다.

```javascript
db.createUser({
    user: "root",
    pwd: "비밀번호",
    roles: [
        {
            role: "root",
            db: "admin"
        }
    ]
})
```

생성된 사용자를 확인합니다.

```javascript
db.getUsers()
```

`root` 사용자가 보이면 정상입니다.

주의할 점은 `roles` 안에 `db: "admin"`을 적는 것과 사용자를 `admin` 데이터베이스에 생성하는 것은 다른 개념이라는 점입니다. `db.createUser()`는 현재 선택된 데이터베이스에 사용자를 생성합니다. 따라서 root 계정을 만들기 전에는 반드시 `use admin`을 먼저 실행해야 합니다.

## 12. Mongo Shell 종료

계정 생성이 끝나면 Shell을 종료합니다.

```bash
exit
```

## 13. MongoDB 인증 활성화

MongoDB 설정 파일을 수정합니다.

```bash
sudo vi /etc/mongod.conf
```

아래 설정을 추가합니다.

```yaml
security:
  authorization: enabled
```

예시는 아래와 같습니다.

```yaml
net:
  port: 27017
  bindIp: 127.0.0.1

security:
  authorization: enabled
```

`vi` 저장 방법은 다음과 같습니다.

```text
ESC
:wq
```

MongoDB를 재시작합니다.

```bash
sudo systemctl restart mongod
```

## 14. root 계정 로그인 확인

인증이 활성화된 상태에서 root 계정으로 로그인합니다.

```bash
mongosh --username root --authenticationDatabase admin
```

비밀번호를 입력하면 접속됩니다.

비밀번호를 명령어에 직접 넣는 방식도 가능하지만, 운영 서버에서는 터미널 히스토리에 비밀번호가 남을 수 있으므로 위 방식처럼 비밀번호를 입력받는 방식을 권장합니다.

## 15. 티에이치스터디 Database 생성

root 계정으로 접속한 상태에서 서비스용 데이터베이스를 생성합니다.

```javascript
use th_study
```

Collection을 생성합니다.

```javascript
db.createCollection("access_logs")

db.createCollection("bot_logs")
```

생성된 Collection을 확인합니다.

```javascript
show collections
```

아래처럼 표시되면 정상입니다.

```text
access_logs
bot_logs
```

## 16. 서비스 계정 생성

실제 애플리케이션이나 MongoDB Compass에서는 root 계정보다 서비스 계정을 사용하는 것이 좋습니다.

`th_study` 데이터베이스에서 서비스 계정을 생성합니다.

```javascript
db.createUser({
    user: "th_study",
    pwd: "비밀번호",
    roles: [
        {
            role: "readWrite",
            db: "th_study"
        }
    ]
})
```

`readWrite` 권한은 해당 데이터베이스에 대해 읽기와 쓰기 권한을 부여합니다. root 계정은 관리자 작업용으로만 사용하고, 애플리케이션에서는 서비스 계정을 사용하는 것이 일반적입니다.

## 17. 서비스 계정 로그인 테스트

Shell을 종료합니다.

```bash
exit
```

서비스 계정으로 로그인합니다.

```bash
mongosh --username th_study --authenticationDatabase th_study
```

비밀번호를 입력하면 접속됩니다.

특수문자가 포함된 비밀번호를 URI 방식으로 입력할 경우 Linux Shell에서 문제가 생길 수 있으므로, 위처럼 비밀번호를 직접 입력받는 방식을 권장합니다.

## 18. 테스트 데이터 저장

서비스 계정으로 접속한 상태에서 테스트 데이터를 저장합니다.

```javascript
db.bot_logs.insertOne({
    ip: "127.0.0.1",
    bot_name: "Googlebot"
})
```

## 19. 테스트 데이터 조회

저장된 데이터를 조회합니다.

```javascript
db.bot_logs.find()
```

데이터가 출력되면 정상입니다.

## 20. 인덱스 생성

MongoDB도 데이터가 많아지면 인덱스가 필요합니다.

예를 들어 IP 기준으로 조회가 자주 발생한다면 `ip` 필드에 인덱스를 생성할 수 있습니다.

```javascript
db.access_logs.createIndex({
    ip: 1
})
```

생성된 인덱스를 확인합니다.

```javascript
db.access_logs.getIndexes()
```

## 21. MongoDB Compass 외부 접속 허용

MongoDB Compass에서 AWS Lightsail 서버의 MongoDB에 접속하려면 MongoDB가 외부 접속을 받을 수 있어야 합니다.

설정 파일을 수정합니다.

```bash
sudo vi /etc/mongod.conf
```

기존 설정은 보통 아래와 같습니다.

```yaml
net:
  port: 27017
  bindIp: 127.0.0.1
```

외부 접속을 허용하려면 아래처럼 변경합니다.

```yaml
net:
  port: 27017
  bindIp: 0.0.0.0
```

변경 후 MongoDB를 재시작합니다.

```bash
sudo systemctl restart mongod
```

포트 바인딩 상태를 확인합니다.

```bash
sudo ss -tulpn | grep 27017
```

아래처럼 보이면 외부 접속을 받을 수 있는 상태입니다.

```text
0.0.0.0:27017
```

만약 아래처럼 보이면 아직 외부 접속이 불가능한 상태입니다.

```text
127.0.0.1:27017
```

## 22. AWS Lightsail 방화벽 설정

AWS Lightsail 콘솔에서 인스턴스의 네트워킹 설정으로 이동합니다.

IPv4 방화벽에서 규칙을 추가합니다.

```text
애플리케이션: 사용자 지정
프로토콜: TCP
포트: 27017
소스 IP 주소: 모든 IPv4 주소
```

테스트 목적이라면 모든 IPv4 주소로 열 수 있지만, 운영 환경에서는 가능한 한 본인 IP만 허용하는 것이 좋습니다.

MongoDB 항목이 따로 없어도 정상입니다. Lightsail 방화벽에서는 MongoDB가 기본 애플리케이션 목록에 없기 때문에 사용자 지정 TCP 포트로 27017을 추가하면 됩니다.

## 23. MongoDB Compass 접속

MongoDB Compass에서는 URI 방식보다 입력 폼을 사용하는 방식이 편합니다.

General 설정은 아래와 같이 입력합니다.

```text
Hostname: 서버 IP
Port: 27017
```

Authentication 설정은 root 테스트 기준으로 아래처럼 입력합니다.

```text
Authentication Method: Username/Password
Username: root
Password: root 비밀번호
Authentication Database: admin
```

서비스 계정으로 접속할 경우 아래처럼 입력합니다.

```text
Authentication Method: Username/Password
Username: th_study
Password: 서비스 계정 비밀번호
Authentication Database: th_study
```

운영 원칙상 root 계정은 관리자 작업용으로만 사용하고, 평소에는 서비스 계정으로 접속하는 것이 좋습니다.

## 24. root 계정과 서비스 계정 사용 원칙

`bindIp`는 계정별 접속 제한이 아니라 네트워크 접근 범위를 제어합니다.

예를 들어 아래처럼 설정하면 모든 계정이 외부에서 접속할 수 없습니다.

```yaml
bindIp: 127.0.0.1
```

아래처럼 설정하면 외부 네트워크에서 MongoDB에 접근할 수 있습니다.

```yaml
bindIp: 0.0.0.0
```

따라서 외부 접속을 허용해야 하는 경우에는 계정 권한을 분리하는 것이 중요합니다.

root 계정은 관리자 작업에만 사용하고, 애플리케이션이나 Compass에서는 `readWrite` 권한만 가진 서비스 계정을 사용하는 것이 좋습니다.

## 25. 참고. URI 방식으로 접속하기

URI 방식으로 접속할 수도 있습니다.

```bash
mongosh 'mongodb://th_study:비밀번호@localhost:27017/th_study'
```

비밀번호에 `!`, `$`, `#`, `&`, `@` 같은 특수문자가 포함되어 있으면 Linux Shell에서 오류가 발생할 수 있습니다. 이 경우 전체 URI를 작은따옴표로 감싸야 합니다.

예시는 아래와 같습니다.

```bash
mongosh 'mongodb://th_study:Op_th_study2026!@localhost:27017/th_study'
```

Compass URI 입력창에서는 `#` 같은 문자는 URL 인코딩이 필요할 수 있습니다.

예를 들어 비밀번호가 아래와 같다면

```text
Ceman08079#
```

URI에서는 `#`를 `%23`으로 바꿔야 합니다.

```text
mongodb://root:Ceman08079%23@서버IP:27017/admin
```

하지만 이런 문제 때문에 Compass에서는 URI 직접 입력보다 Username, Password, Authentication Database를 각각 입력하는 방식을 권장합니다.

## 26. 참고. MongoDB 8.3.4가 설치된 경우 8.3.3으로 맞추기

처음 설치 과정에서 최신 버전인 8.3.4가 설치되었고, 로컬 개발 환경과 맞추기 위해 8.3.3으로 변경해야 한다면 아래 명령을 사용할 수 있습니다.

이 작업은 일반 설치 순서가 아니라 버전 조정이 필요한 경우에만 진행합니다.

```bash
sudo apt install -y --allow-downgrades \
mongodb-org=8.3.3 \
mongodb-org-database=8.3.3 \
mongodb-org-server=8.3.3 \
mongodb-org-mongos=8.3.3 \
mongodb-org-tools=8.3.3
```

변경 후 버전을 확인합니다.

```bash
mongod --version
```

## 27. 참고. 인증 실패가 발생하는 경우

아래 오류가 발생할 수 있습니다.

```text
MongoServerError: Authentication failed.
```

이 경우 가장 먼저 root 계정이 실제로 `admin` 데이터베이스에 생성되었는지 확인해야 합니다.

인증을 잠시 끄고 MongoDB에 접속한 뒤 확인합니다.

```bash
sudo vi /etc/mongod.conf
```

아래 설정을 잠시 주석 처리합니다.

```yaml
# security:
#   authorization: enabled
```

MongoDB를 재시작합니다.

```bash
sudo systemctl restart mongod
```

인증 없이 접속합니다.

```bash
mongosh
```

admin 데이터베이스로 이동합니다.

```javascript
use admin
```

사용자를 확인합니다.

```javascript
db.getUsers()
```

`users: []`로 나오면 admin 데이터베이스에 root 계정이 생성되지 않은 상태입니다.

이 경우 다시 `use admin`을 먼저 실행한 뒤 root 계정을 생성해야 합니다.

```javascript
use admin

db.createUser({
    user: "root",
    pwd: "비밀번호",
    roles: [
        {
            role: "root",
            db: "admin"
        }
    ]
})
```

그 다음 인증 설정을 다시 활성화합니다.

```yaml
security:
  authorization: enabled
```

MongoDB를 재시작합니다.

```bash
sudo systemctl restart mongod
```

이후 root 계정으로 다시 로그인합니다.

```bash
mongosh --username root --authenticationDatabase admin
```

## 28. 정리

이 과정을 완료하면 AWS Lightsail Ubuntu 22.04 운영 서버에 MongoDB Community Server 8.3.3 설치, root 관리자 계정 생성, 인증 활성화, 티에이치스터디용 `th_study` 데이터베이스 생성, `access_logs`, `bot_logs` Collection 생성, 서비스 계정 생성, 테스트 데이터 저장, 인덱스 생성, MongoDB Compass 접속까지 완료됩니다.

운영 서버에서는 root 계정을 애플리케이션에서 직접 사용하지 않고, 서비스 계정을 분리해서 사용하는 것이 좋습니다. 또한 외부 접속을 허용할 때는 Lightsail 방화벽과 MongoDB `bindIp` 설정을 함께 확인해야 합니다.
