# 게시판 개발 스킬 규격 (Board Skill Spec)

## 0) 목표 (Goal)
- 라라벨 게시판 CRUD를 **Controller / Service / Repository** 계층 분리로 구현한다.
- 권한은 **Policy**로 통제한다.
- 유효성 검사는 **FormRequest**로 처리한다.
- 게시글(Post)과 댓글(Comment)의 모든 작업(등록/수정/삭제/조회)을 **히스토리(th_post_histories)**로 기록한다.
  - 게시글: table_type = `th_posts`
  - 댓글: table_type = `comment`
- 게시글/댓글 등록 시 **메일 알림(Queue)** 을 보낸다.
- **등록/수정 페이지는 하나의 Blade에서 통합 처리한다.**
- **리스트는 무조건 paginate(20)** 으로 페이징 처리한다.
- 모든 CRUD/이벤트/메일은 **Log::info()** 로 기록한다.
- 퍼블리싱은 Bootstrap5 + “게시판 CSS 규칙” 준수.

---

# 1) 아키텍처 규칙

## Must
- Controller: HTTP 처리 / redirect / view만 담당
- Service: 비즈니스 로직 전담
- Repository: DB 쿼리 전담
- Policy: 권한 체크
- FormRequest: 유효성 검증
- CRUD/메일/이벤트 발생 시 무조건 `Log::info()`
- 등록/수정 Blade 통합 (액션만 다름)
- 게시글 + 댓글 공통으로 **이력 생성 필수**

## Should
- post_type 검증은 Router/Middleware에서 수행 → Controller 중복 검증은 선택
- 예외 발생 시 try/catch로 로그 남기고 사용자에겐 안전 메시지

# 2) 프론트 유효성 UX 규칙

### Must
#### 상단 status 영역
```blade
@if ($errors->any())
  <div class="alert alert-danger" role="alert">
    에러가 있습니다. 아래 항목을 확인해 주세요.
  </div>
@endif

@if (session('status'))
  <div class="alert alert-success" role="alert">
    {{ session('status') }}
  </div>
@endif
```

#### 필드 규칙
- `old()` 값 유지
- `@error('필드')` 메시지 출력
- 에러 시 `is-invalid` 클래스 적용

#### 등록/수정 페이지 통합
- 생성: `POST /posts/{post_type}`
- 수정: `PUT /posts/{post_type}/{id}`
- 동일 Blade 사용, 버튼만 변경

# 3) DB 규칙

## th_posts (게시글)
- 필수: `post_type`
- 기본값: `status = 대기중`
- 상태 변경은 관리자만 가능

## 댓글 테이블(comment)
- 댓글 테이블명은 프로젝트 구조에 따름
- 이력 기록 시 table_type = `comment`
- 부모 post_type 은 부모 게시글에서 가져옴

---

# 4) 이력 테이블 규칙 (th_post_histories)

### Must (게시글 + 댓글 공통)
#### 필수 컬럼
- `job_type`: 등록 | 수정 | 삭제 | 조회
- `table_type`:  
  - 게시글 = `th_posts`  
  - 댓글 = `comment`
- `post_type`:  
  - 게시글 = 자신의 post_type  
  - 댓글 = 부모 게시글의 post_type
- `create_datetime`
- `create_user_idx`

#### 대상 식별(유도리 규칙)
- 이력에 “대상 id”를 저장하는 컬럼이 **이미 테이블에 존재할 경우**:
  - 예: `post_idx`, `comment_idx`, `ref_idx`, `table_idx` 등  
  → 존재하면 반드시 채움
- 없다면 스키마 변경 없이 진행해도 됨

#### Must
- 게시글 CRUD, 댓글 CRUD, 조회 → 모두 이력 1건 생성

# 6) 메일 알림 규칙 (Queue)

### Must (트리거)
- 게시글 등록 → 메일 발송
- 댓글 등록 → 메일 발송
- 단, **관리자가 작성한 글은 메일 발송 제외**

### 관리자 수신자
- User.level = admin
- 여러 명이면 최대 3명까지 발송

### 구현 방식
- SendMailJob 큐로 처리
- 메일 발송 여부는 개발자 지시  
  → 지시 없으면 먼저 “메일 발송?” 질문

# 8) 로그(Log) 규칙

### CRUD 성공
```php
Log::info('[Post][Create] success', [
  'user_idx' => $user->idx ?? null,
  'post_idx' => $post->idx ?? null,
  'post_type' => $post->post_type ?? null,
]);
```

### 댓글 성공
```php
Log::info('[Comment][Create] success', [
  'user_idx' => $user->idx ?? null,
  'comment_idx' => $comment->idx ?? null,
  'post_idx' => $comment->post_idx ?? null,
]);
```

### 메일 발송
```php
Log::info('[Mail] notification sent', [
  'recipients' => $emails,
  'post_idx' => $post->idx ?? null,
]);
```

### 예외 처리
```php
catch (\Throwable $e) {
  Log::error('[Error]', [
    'message' => $e->getMessage(),
  ]);
  return back()
    ->withErrors(['status' => '오류가 발생했습니다.'])
    ->withInput();
}
```
