# 게시판 개발 스킬 규격 (Board Skill Spec)

## 0) 목표 (Goal)
- 라라벨 게시판 CRUD를 **Controller / Service / Repository** 계층 분리로 구현한다.
- 권한은 **Policy**로 통제한다.
- 유효성 검사는 **FormRequest**로 처리한다.
- 게시글(Post)의 모든 작업(등록/수정/삭제/조회)을 **히스토리(th_post_histories)**에 기록한다.
- **댓글(Comment)은 include/단독 여부와 무관하게 → 추가/등록/수정/삭제/조회 전부 로그/이력 기록 안 한다.**
- 게시글 등록 시 **메일 알림(Queue)**을 보낸다.  
  (댓글은 메일 발송 제외)
- **등록/수정 페이지는 하나의 Blade로 통합한다.**
- **리스트는 paginate(20)** 고정 사용.
- 모든 게시글 CRUD/메일/이벤트는 **Log::info()** 사용.
- 퍼블리싱은 Bootstrap5 + 게시판 CSS 규칙 따른다.

---

# 1) 아키텍처 규칙

## Must
- Controller → request, response, view 렌더링
- Service → 비즈니스 로직
- Repository → DB 접근
- Policy → 권한 체크
- FormRequest → 유효성 검사
- 게시글 CRUD → 반드시 이력 작성 + 로그 기록
- 댓글 CRUD → **이력 X / 로그 X (완전 제외)**
- 등록/수정 Blade 페이지 통합
- 예외는 반드시 try/catch + 로그(error)

## Should
- post_type 검증은 Router/Middleware에서 수행 → Controller는 선택
- 브라우저 UI에서 form old(), error 메시지, invalid class 적용

---

# 2) 프론트 유효성 UX 규칙

### Must — 상단 status 영역
```blade
@if ($errors->any())
  <div class="alert alert-danger" role="alert">
    에러가 있습니다. 아래 항목을 확인해 주세요.
  </div>
@endif

@if (session('status'))
  <div class="alert alert-success" role="alert">
    {{ session('status') }}
  </div>
@endif
```

### 각 필드
- old() 유지  
- @error 출력  
- is-invalid 적용

### 등록/수정 페이지 통합
- 생성 → `POST /posts/{post_type}`
- 수정 → `PUT /posts/{post_type}/{id}`
- 동일 Blade, 버튼만 상황에 맞게 변경

# 3) DB 규칙

## th_posts (게시글)
- 필수: post_type
- status 기본값: `대기중`
- status 변경은 관리자만 가능

## 댓글(comment)
- CRUD 가능
- **이력 기록 없음**
- **로그 없음**

---

# 4) 이력 테이블 규칙 (th_post_histories)  
**→ 게시글만 기록함. 댓글은 이력 X**

## Must
### 필수 컬럼
- job_type: 등록 | 수정 | 삭제 | 조회
- table_type: `th_posts`
- post_type: 게시글의 post_type
- create_datetime
- create_user_idx

### 대상 식별
- 테이블에 대상 id 컬럼이 존재하면 저장  
  (post_idx 등)
- 없으면 스키마 변경 없이 진행

---

# 5) 리스트 페이지 규칙 (페이징 Must)

### Must
- `paginate(20)` 고정
- links() 렌더링 필수
- 현재 page 번호 로그(info)

---

# 6) 메일 알림 규칙 (Queue)

## Must
- 게시글 등록 시 메일 발송
- **댓글은 메일 발송 제외**
- 관리자(User.level=admin) 3명까지 전송
- 메일 발송 여부는 개발자가 결정 (지시 없으면 먼저 물어봄)

# 8) 로그(Log) 규칙

## 게시글 CRUD만 로그 남김  
(댓글 CRUD → 로그 없음)

### 예시
```php
Log::info('[Post][Create] success', [
  'user_idx' => $user->idx ?? null,
  'post_idx' => $post->idx ?? null,
  'post_type' => $post->post_type ?? null,
]);
```

### 메일
```php
Log::info('[Mail] notification sent', [
  'recipients' => $emails,
  'post_idx' => $post->idx ?? null,
]);
```

### 예외 처리
```php
catch (\Throwable $e) {
  Log::error('[Error]', [
    'message' => $e->getMessage(),
  ]);
  return back()
    ->withErrors(['status' => '오류가 발생했습니다.'])
    ->withInput();
}
```

# 9) 게시판 퍼블리싱 규칙 (Bootstrap 5)

### Must
1. 글 넘침 시 → `board-ellipsis`
2. 모바일 숨김 → `board-col-hidden`
3. 상태 뱃지:  
   - text-bg-secondary  
   - text-bg-warning  
   - text-bg-dark  
   - text-bg-success
4. 정렬 클래스:  
   - text-start / text-center / text-end
5. 줄바꿈 방지 → text-nowrap  
6. 리스트 모든 td에 ellipsis/nowrap 적용

---

# 10) 게시판 CSS 클래스 규칙

### Must
- `.board-col-hidden` → 모바일 숨김
- `.board-ellipsis` → 줄임표(...)
- 정렬: `text-start`, `text-center`, `text-end`
- 줄바꿈 방지: `text-nowrap`
- 상태 뱃지:
```blade
<span class="badge text-bg-{{ $badgeClass }}">상태</span>
```
