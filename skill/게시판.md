# 📘 게시판 개발 스킬 규격 (Board Skill Spec) — TH-Study-Group 기준

## 0) 목표 (Goal)
- 게시판 CRUD를 **Controller / Service / Repository** 계층 분리로 개발한다.
- 권한은 **Policy**로 통제한다.
- 유효성 검사는 **FormRequest**로 처리한다.
- 게시글(Post)과 댓글(Comment) 처리 시  
  - 게시글은 전체 이력 기록  
  - 댓글은 “단독 페이지에서만 이력 기록 / include 조회는 이력 제외”
- 게시글 등록 시 필요 시 관리자에게 메일 알림(Queue).
- **등록/수정은 동일 Blade에서 처리한다.**
- **리스트는 paginate(20)** 고정.
- 게시글 CRUD/메일/이벤트는 `Log::info()` 기록한다.
- 게시판 퍼블리싱은 Bootstrap5 + 게시판 CSS 규칙을 따른다.

---

# 1) 기본 아키텍처 규칙

## Must
- Controller → request/response/redirect/view
- Service → 비즈니스 로직
- Repository → DB
- Policy → 권한
- FormRequest → 유효성
- 게시글 CRUD → 이력 Must + 로그 Must
- 댓글 CRUD → 단독 페이지에서만 이력/로그 Must, include 조회는 이력/로그 Never
- 예외 발생 시 try/catch + error 로그 + 사용자 안전 메시지
- 등록/수정 페이지는 하나의 Blade로 통합

# 3) DB 규칙 (Posts)

## th_posts (게시글) 공통
### Must
- `post_type` 필수
- `status` 기본값 = `wait`
- `use_flag` 기본값 = `Y`

> 결론: **모든 게시판은 status=wait 기본값으로 시작해도 되고**,  
> **노출/비노출은 use_flag(Y/N)**,  
> **업무 처리상태는 status(wait 등)로 제어**한다.

---

# 4) 게시판 유형별 상태/노출 규칙 (중요)

## A) 공지사항 / 자유게시판 (고객 노출형)
### Must
- `status = wait` 기본값 유지 (상태값은 운영상 큰 의미 없음)
- 고객에게 보이는 글 제어는 `use_flag` 로 한다.
  - `use_flag = Y` → 고객 화면에 노출
  - `use_flag = N` → 고객 화면에 비노출 (작성/검수/숨김)

### 이유
- 공지/자유는 “고객에게 바로 노출될 수 있는 글”이라  
  status(wait)는 의미가 애매하고,  
  **노출 제어는 use_flag가 더 명확**하다.

---

## B) 문의사항(1:1) / 처리·승인 절차가 필요한 게시판
### Must
- `use_flag = Y` 기본값 (기본적으로 존재/사용되는 글)
- 처리 상태(대기/처리중/완료/반려 등)는 `status` 로 제어한다.
  - status 기본값은 wait (대기)

### 이유
- 문의/승인형은 핵심이 “업무 흐름”이므로  
  **노출 여부보다 처리 상태(status)가 중요**하다.
- 그래도 필요하면 use_flag로 “숨김/비활성”도 가능.

---

# 5) 댓글(Comment) 규칙

## 댓글 이력/로그 규칙 (최종)
### Must — 단독 페이지에서만 기록
- 댓글 단독 페이지(`/comments/{id}` 등)에서 발생한:
  - 등록 / 수정 / 삭제 / 조회  
  → **이력 기록 + 로그 기록**

### Never — include 댓글은 기록하지 않음
- 게시글 상세(`/posts/{id}/show`)에서 댓글이 include로 로드되는 경우:
  - 조회/렌더링/목록 표시 등  
  → **이력/로그 기록하지 않음**
- 이유: 댓글 batch 로딩 시 이력 폭발 방지 + 게시글 조회 이력으로 충분

# 6) 이력 테이블 규칙 (th_post_histories)

## A) 게시글(Post) — Must
### 필수 컬럼
- job_type: 등록 | 수정 | 삭제 | 조회
- table_type: `th_posts`
- post_type: 게시글 post_type
- create_datetime
- create_user_idx

### 대상 ID 처리(유도리)
- 테이블에 대상 ID 컬럼(post_idx 등)이 있으면 저장
- 없으면 스키마 변경 없이 진행

---

## B) 댓글(Comment) — Must(단독만)
### 단독 페이지에서 CRUD 발생 시만 기록
- job_type: 등록 | 수정 | 삭제 | 조회
- table_type: `comment`
- post_type: 부모 게시글 post_type
- create_datetime
- create_user_idx

### include 댓글은 기록하지 않음

# 10) 로그(Log) 규칙

## 게시글 CRUD 로그 (Must)
```php
Log::info('[Post][Create] success', [
  'user_idx' => $user->idx ?? null,
  'post_idx' => $post->idx ?? null,
  'post_type' => $post->post_type ?? null,
  'status' => $post->status ?? null,
  'use_flag' => $post->use_flag ?? null,
]);
```

## 댓글 단독 CRUD 로그 (Must)
```php
Log::info('[Comment][Action]', [
  'user_idx' => $user->idx ?? null,
  'comment_idx' => $comment->idx ?? null,
  'post_idx' => $comment->post_idx ?? null,
]);
```

## include 댓글(게시글 상세 내) — 로그 없음

## 예외 처리
```php
catch (\Throwable $e) {
  Log::error('[Error]', ['message' => $e->getMessage()]);
  return back()->withErrors(['status' => '오류가 발생했습니다.'])->withInput();
}
```
