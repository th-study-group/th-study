# Note 메뉴 개발 (Codex Skill File)

## 개요
- 티에이치스터디의 다양한 정보를 관리하는 노트 기능을 구현한다.
- 구조: 그룹 → 카테고리 → 주제.
- 그룹 및 기본 카테고리:
  - blogs: 개발, 여행, 맛집, 카페, 경제
  - photos: 음식, 카페, 여행
  - maps: 음식, 카페, 여행, 추억
  - documents: 회사자료, 학습자료, 개발자료
  - videos: 개발, 여행, 음악
- 그룹/카테고리는 추후 확장 가능.
- 각 카테고리는 여러 주제를 가질 수 있다. (예: 블로그/개발 → “라라벨기초”, “라라벨 개발환경 구성”)
- 노트 작성에 필요한 주요 키: group, category, topic.
- 노트 작성 시 해시태그를 최대 10개까지 등록(노트-태그 다대다).
- 노트의 작성/수정/삭제/조회는 모두 히스토리 기록(기존 게시판 이력과 유사).
- 게시판 규칙은 `/Users/developerkimtakgu/th-study/skill/게시판.md` 파일의 구조·패턴을 따른다.

## 노트 그룹 확장과 연동 점검

- 화면 그룹명과 DB 그룹 코드는 다를 수 있다. 새 그룹을 추가하거나 변경할 때는 `config/note.php`의 그룹 설정, `note_groups.code`, 라우트 prefix를 함께 확인하고 기존 `blog` 값을 다른 그룹에 그대로 사용하지 않는다.
- 현재 홈 최신 콘텐츠와 그 캐시는 블로그 전용이다. 새 그룹을 홈에 노출하거나 해당 그룹 전용 캐시를 추가하는 경우에만 조회 범위, 캐시 resource/context 키, 생성·수정·삭제·공개 전환 시 캐시 무효화를 함께 설계한다.
- 새 그룹을 추가한다는 이유만으로 기존 블로그 캐시를 일반화하거나 무효화 대상에 포함하지 않는다. 캐시 대상과 표시 위치가 확정되지 않았다면 사용자에게 필요한 캐시 변경 여부와 범위를 먼저 알리고 승인 범위에 포함한다.
- 그룹별 상세 URL을 유입통계(`access_page`), sitemap, 공유 메타, 조회 이력에 연결하는 경우에는 해당 그룹의 실제 route 이름과 URL 형식을 기준으로 각각 적용 여부를 확인한다. 블로그 전용 경로(`/blogs/...`)나 블로그의 조회 이력 정책을 다른 그룹에 임의로 복사하지 않는다.
- 공개 노트를 검색 노출할 그룹으로 결정한 경우에만 sitemap 대상, 공개 여부(`use_flag`), `lastmod` 기준을 함께 검토한다. 검색 노출 요구가 없는 그룹은 sitemap에 자동 추가하지 않는다.

## 라우팅
- GET    /{group}                       — 글 목록
- GET    /{group}/{slug}/{idx}/show    — 상세조회
- GET    /{group}/{slug}/create        — 작성폼
- POST   /{group}/{idx}                — 작성처리
- GET    /{group}/{slug}/{idx}/edit    — 수정폼
- PUT    /{group}/{slug}/{idx}         — 수정처리
- DELETE /{group}/{slug}/{idx}         — 삭제처리

### 라우팅 규칙
- {group}, {slug} 값은 DB에 실제 존재하는지 반드시 체크한다.
- 이 검증은 라우팅 또는 미들웨어에서 처리한다.
- 현재는 라우팅 및 미들웨어에서 해당 값을 막고 있다.

## 구현 구조
- Controller → Service → Repository 구조로 구현한다.
- FormRequest를 통해 모든 입력값을 검증한다.
- 각 클래스(Service/Repository/Controller)는 로그를 남긴다.
- 게시판 구조를 노트에도 그대로 적용한다.
- 노트는 별도의 관리자 페이지 없이 메뉴에서 직접 수정/관리한다.

---

## 권한 (Policy)
- 조회는 전체 허용.
- 추가/수정/삭제/게시글 공개여부 설정은 `user.level = admin`만 가능.
- 게시글 작성 시 공개여부 기본값은 **비공개**로 설정한다.
- 공개여부 설정 UI는 **상세 페이지와 수정 페이지에서만** 노출한다.
- 권한이 없으면 해당 버튼은 UI에 렌더링하지 않는다(버튼 비노출).
- Policy 결과를 기준으로 버튼 노출 여부를 제어한다.

## 이미지 업로드
- 에디터 업로드가 아닌 **파일 업로드 방식**으로 이미지를 처리한다.
- 업로드된 이미지는 노트의 썸네일로 사용한다.
- 저장 경로: `storage/app/public`
- 저장 폴더명 규칙: `YYYYMM` (예: `202602`)
- 노트 수정 시 썸네일 이미지를 삭제할 수 있으며, 삭제 시 실제 파일을 완전히 제거한다.
- 썸네일이 업로드되지 않은 경우 목록에서는 `public/images/no_image.png` 를 기본 이미지로 사용한다.
- 업로드된 파일은 2주 후 삭제(백업/정리 정책).

### 아이폰/맥북 썸네일 저장 시 처리 규칙
1) 아이폰 사진은 EXIF에만 회전 정보가 있는 경우가 많으므로 `orientate()` 등으로 EXIF 기준 자동 회전 보정을 적용한다.  
2) 해상도가 큰 이미지는 가로 최대 1600px로 리사이즈한다.  
3) PNG는 PNG 그대로 저장하여 투명/그래픽 정보를 유지한다.  
4) JPEG 계열 이미지는 JPG로 압축 저장한다.  
5) 목적: 용량, 메모리 사용량, 트래픽을 줄이기 위함.

## 해시태그
- 노트 1건 작성 시 해시태그는 최대 10개까지 등록할 수 있다.
- 노트와 해시태그는 다대다 구조이며, `th_note_tag_map`으로 연결한다.

## 히스토리
- 노트의 추가/수정/삭제, 공개여부 등 설정 변경 시 모두 `th_note_histories` 테이블에 저장한다.
- 히스토리 저장은 로그인 이력, 게시판 이력과 동일하게 이벤트 기반으로 처리한다.
